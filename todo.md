- [x] **Build/release workflow was spamming failure emails on every push — fixed 2026-08-30.** `.github/workflows/build.yml` ran a full signed-release build (Windows DigiCert signing, macOS notarization) on `on: push` — i.e. every commit to every branch. Those signing steps need paid credentials (DigiCert cert, Apple Developer cert/notarization key) that were configured as secrets on OpenBuilds' original repo and never carried over to `drb2023/ConcatCNC`, so the Windows job failed within ~1 minute on every push and GitHub's matrix `fail-fast` cancelled the macOS/Ubuntu jobs alongside it. Changed the trigger to `push: tags: ['v*']` so it only runs when you push an actual release tag, matching how the README's release links work.
  - [ ] **Still needed before a real release build will succeed:** the workflow still expects `SM_CLIENT_CERT_FILE_B64`/`SM_CODE_SIGNING_CERT_SHA1_HASH`/`SM_HOST`/`SM_API_KEY`/`SM_CLIENT_CERT_PASSWORD` (DigiCert Windows signing) and `mac_certs`/`mac_certs_password`/`APPLE_ID`/`APPLE_ID_PASSWORD`/`APPLE_TEAM_ID`/`api_key`/`api_key_id`/`api_key_issuer_id` (Apple notarization) as GitHub repo secrets. Until you have your own DigiCert/Apple Developer credentials (or decide to ship unsigned builds and strip the signing steps), pushing a `v*` tag will still fail the same way — just only when you actually mean to cut a release, not on every commit.
